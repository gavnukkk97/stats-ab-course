# Как обновлять курс

Эта инструкция — для авторов уроков и тех, кто меняет расчёты, рисунки или структуру репозитория. Чтобы учиться по курсу, достаточно [основного README](../README.md) и зависимостей из `requirements.txt`.

## Где вносить изменения

Основной источник учебного материала — `course/`. У каждого модуля один и тот же порядок:

```text
course/modules/M1/
  README.md              Оглавление модуля
  lesson-1.1.md          Урок
  practice/
    practice_1_1.py      Готовый исполняемый разбор
  exercises/
    exercise_1_1.py      Самостоятельное задание с пропусками
  images/
    …png                Схемы и результаты практик
```

Папки `exercises/` с заготовками пока есть в M1 и M2. Общая тетрадь заданий находится в [course/exercises](../course/exercises/README.md), итоговый проект — в [course/capstone](../course/capstone/README.md). Файлы с заданиями могут содержать намеренно незаполненный код: их не нужно добавлять в прогон готовых практик.

Общие вычислительные функции размещайте в `course/lib/`. Иллюстрации модуля — в его `images/`; общую карту маршрута — в `course/images/`; изображения кейсов — в `course/cases/images/`; изображения справочника — в `skills/<имя>/images/`. Не складывайте рисунки рядом с текстами уроков или генераторами.

Генераторы поясняющих схем находятся в `scripts/figures/`. Графики результатов создают сами практики. Сохраняйте вывод относительно местоположения файла или корня проекта, чтобы запуск не зависел от текущего каталога пользователя.

## Окружение

Проверенная версия Python — 3.13. Команды ниже выполняются из корня репозитория в активированном окружении. Для macOS и Linux:

```sh
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements/dev.txt
```

На Windows можно создать окружение через `py -3.13 -m venv .venv` и запускать все команды через `.venv\Scripts\python.exe` вместо `python`.

Наборы зависимостей разделены по назначению:

| Файл | Когда нужен |
|---|---|
| [requirements.txt](../requirements.txt) | Основные практики и генераторы рисунков |
| [requirements/dev.txt](../requirements/dev.txt) | Основные зависимости и запуск тестов |
| [requirements/bayes.txt](../requirements/bayes.txt) | Практика 5.5 с PyMC и ArviZ; включает основные зависимости |
| [requirements/verified.txt](../requirements/verified.txt) | Снимок пакетов проверенной установки для сверки версий |

Снимок проверенной установки не гарантирует одинаковую сборку на любой системе. Для обычной работы используйте набор по назначению; `.venv/` не добавляйте в репозиторий.

## Изменение урока или расчёта

1. Отредактируйте материал в `course/` и связанные справочники в `skills/`.
2. Если меняется расчёт, запустите соответствующую практику и проверьте условия метода, единицы измерения и вывод. Успешное завершение программы само по себе не подтверждает корректность статистики.
3. Если меняется объяснение на рисунке, обновите его генератор, пересоздайте PNG и откройте результат: проверьте подписи, обрезку текста и соответствие уроку.
4. При добавлении темы обновите оглавление модуля, задания и при необходимости [навигацию](../course/NAVIGATION.md), [зависимости тем](../course/PREREQUISITES.md) и [словарь](../course/GLOSSARY.md).
5. Выполните проверки и синхронизируйте Obsidian по командам ниже.

Числа в тексте и подписях должны соответствовать воспроизводимому примеру. Если результат зависит от симуляции, укажите seed и погрешность там, где это влияет на вывод. Для нового метода добавьте первоисточник и существенные допущения; не превращайте частный пример в универсальную гарантию.

## Рисунки и практики

Пересоздать рисунки одной практики:

```sh
python course/modules/M1/practice/practice_1_1.py
```

Пересоздать поясняющие схемы курса:

```sh
python scripts/generate_figures.py
```

Для одного модуля: `python scripts/generate_figures.py --module M1`. Журналы и отчёт генерации сохраняются в `build/figures/`. Справка по выборочному запуску доступна через `python scripts/generate_figures.py --help`. Этот запуск строит схемы из `scripts/figures/`; он не заменяет выполнение практик. PNG сохраняются в соответствующие папки `images/` и входят в репозиторий, чтобы уроки можно было читать без запуска Python.

Сравните изменившиеся рисунки визуально. Рендеринг шрифтов и метаданные PNG могут отличаться между средами; одинаковое имя файла или отсутствие ошибки ещё не означает, что рисунок правильный.

## Проверки

Быстрый цикл после правок:

```sh
python -m pytest tests
python scripts/sync_course.py
python scripts/check_course.py
python scripts/sync_course.py --check
git diff --check
```

Тесты проверяют численные примеры и правила решений. `check_course.py` проверяет синтаксис Python и локальные ссылки в материалах, включая ссылки Obsidian. `sync_course.py --check` ничего не меняет и сообщает о расхождениях зеркала. Эти проверки дополняют чтение текста и просмотр рисунков.

Полный прогон всех готовых практик, включая MCMC, выполняется отдельно:

```sh
python -m pip install -r requirements/bayes.txt
python scripts/check_course.py --run-practices
```

Это длительный запуск: практики выполняются последовательно, для каждой действует ограничение времени. Скрипт показывает статусы, сохраняет отчёт в `build/validation-results.json`, подробные журналы — во временной папке и выводит её путь. Папка `build/` не входит в репозиторий. Проверьте сообщения об ошибках и диагностики моделей; при изменении только текста полный прогон обычно не нужен.

## Версия для Obsidian

`obsidian-vault/Уроки/M1/`–`M7/` — копии модулей с той же внутренней структурой; `Уроки/Кейсы/` — копия кейсов. Общие функции находятся в `obsidian-vault/lib/`. Навигация доступна в корне хранилища; актуальная программа — в `Уроки/plan-курса.md`.

Исправляйте уроки, код и изображения в `course/`, затем запускайте:

```sh
python scripts/sync_course.py
python scripts/sync_course.py --check
```

Не редактируйте копии уроков отдельно: следующая синхронизация перезапишет их. Самостоятельные заметки с понятиями и связями внутри хранилища поддерживаются отдельно и сохраняются при синхронизации. Синхронизация обновляет относительные ссылки и удаляет неизменённые устаревшие копии по `.course-sync-manifest.json`. Если удалённый исходник имеет изменённую вручную копию, она сохраняется, а скрипт сообщает о конфликте. После переноса или удаления материала проверьте результат командой `--check`.

## История и результаты проверок

В `docs/maintenance/` хранятся [исходный аудит](maintenance/COURSE_REVIEW.md), [журнал доработок](maintenance/COURSE_CHANGES.md) и [сохранённый результат проверки](maintenance/validation.json). Аудит описывает прежнее состояние; его замечания не следует автоматически считать текущими ошибками.

Для существенных изменений обновляйте журнал: что исправлено, каким способом проверено и что остаётся непроверенным. Не подменяйте сохранённый результат проверки отчётом о предполагаемом запуске. Изменения учебной последовательности и оценки времени полезно отдельно проверять на читателях.
