- **3.1 «Дизайн: размер выборки, MDE, мощность»**: формула n через MDE ДЛЯ ДВУХ ВЫБОРОК (главное — множитель 2, разбор ошибки из поста shelter: 8711 vs 17422); MDE как бизнес-решение (какой эффект нам интересен, а не «какой получится»); баланс сплита r=0.5 оптимален (мощность 0.79 vs 0.64 при 10/90 — koch-kir); почему нельзя «продлить тест до прокраса» (мощность/MDE живут ТОЛЬКО на этапе дизайна — Atlamos); длительность: недельная сезонность, полные циклы; A/A-проверка дизайна (синтетические A/A — Симулятор 4). - **3.2 «Юнит рандомизации и анализа»**: user vs session vs order vs cluster (geo/курьер); правило: анализ на юните рандомизации (koch-kir); нарушение независимости → заниженные SE → ложная значимость (симуляционно покажи); кластерные SE (CLT по кластерам); ICC и design effect = 1+(m−1)·ICC — эффективный n; когда юнит анализа мельче юнита рандомизации — мостик к ratio (3.3). Практика (practice_3_2.py): симуляция: заказы юзеров с внутрикластерной корреляцией — доля p<0.05 у наивного t по заказам vs по юзерам vs кластерные SE; ICC оценка данными; design effect и эффективный n для своих данных.
- **3.3 «Ratio-метрики: средний чек, CTR»**: почему t-тест в лоб некорректен (числитель/знаменатель зависимы, юниты зависимы — Atlamos); три способа: (1) бутстрап юзерами (семплить юнит целиком — из М1.4), (2) дельта-метод (формула Var(X/Y) через ковариации, вывод не обязателен, механика понятна), (3) линеаризация: сигнал юзера = числитель − ratio_контроля×знаменатель, then поюзерный t-тест; свойства: сонаправленность с глобальной метрикой, открывает CUPED/стратификацию (Atlamos); редкие события/малые n — дельта-метод и линеаризация совпадают при n>100 (koch-kir). Практика (practice_3_3.py): датасет юзеров (заказы с чеками): посчитать глобальный средний чек; A/B-тест: (а) наивный t по заказам — показать сломанный уровень в A/A; (б) бутстрап юзерами; (в) дельта-метод руками (ковариационная матрица); (г) линеаризация + t; сравнить p-value всех четырёх в A/A (уровень) и в A/B (мощность).
