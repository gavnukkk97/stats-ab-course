# Байесовский A/B и бандиты

## Когда байес лучше частотного
- нужно говорить с бизнесом на языке вероятностей: «P(B>A)=93%» продаётся лучше p=0.07
- маленькие выборки + есть исторические данные (empirical Bayes-априор)
- дорогое решение с порогом потерь (expected loss)

## Быстрый пайплайн (конверсии, без MCMC)

1. Апостериоры: A ~ Beta(1+успехи_A, 1+неудачи_A), B аналогично (априор Beta(1,1); информативный — если есть история)
2. Монте-Карло 100k сэмплов → **P(B>A)** = доля(β_B > β_A)
3. **Expected Loss** = mean(max(A−B, 0)) — «сколько теряем, если катим B, а он хуже»
4. Стоп, когда EL < порога жалости (threshold of caring, напр. 0.1 п.п. конверсии)

## Словарь перевода
p-value (односторонний) 0.17 ≈ P(B>A)=91%; p=0.047 ≈ 98%; это одно и то же по-разному.

## Честные оговорки
- Байес НЕ лечит подглядывание: ежедневный стоп по P>95% даёт ~23% ложных побед (как peeking). Лечит цену решения (EL), не error rate
- Спекулятивный априор при малых n опасен — проверяй чувствительность
- Credible ≠ confidence: «вероятность 95% параметр здесь» — это байесовская валюта

## Бандиты (Thompson sampling) вместо теста
- когда: короткие кампании, мгновенная метрика, дорого каждый показ, нужен не вывод, а оптимизация
- как: сэмплируем θ из апостериоров каждой руки → показываем руку с лучшим сэмплом; трафик сам утекает к лучшей
- не когда: нужен отчёт с гарантиями (эффект±CI), нестационарность без окна, network effects

## Иерархические модели (много сегментов/городов)
Вместо «нарезка + Холм» (часто «ничего») — partial pooling: маленькие города тянутся к среднему (shrinkage w=n/(n+κ)), глобальный эффект с HDI. PyMC — рабочий инструмент.
