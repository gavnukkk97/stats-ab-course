# Байесовский A/B и бандиты

## Когда использовать

Когда нужна вероятность практически важного эффекта, ожидаемая стоимость решения или частичное заимствование между сопоставимыми сегментами. Ясно назовите модель, prior и целевой эффект: вероятность условна на них.

## Пайплайн для независимых пользовательских конверсий

1. Зафиксируйте популяцию, бизнес-порог, guardrails, функцию потерь и остановку. Для повторных событий/кластеров Beta–Binomial по событиям не подходит автоматически.
2. При prior Beta(a,b) posterior = Beta(a+успехи,b+неудачи). Beta(1,1) равномерный; Beta(1/2,1/2) — Jeffreys, он не равномерный. Исторический prior оценивайте по независимой сопоставимой истории, учитывая шум конверсий.
3. Из совместных posterior draws вычислите Δ=B−A, P(Δ>0), P(Δ>практического порога), credible interval.
4. EL_B=E[max(A−B,0)|D], EL_A=E[max(B−A,0)|D]. Это безусловная по posterior потеря: в мирах с правильным выбором она нулевая. Она не равна потере условно на ошибке.
5. Выбирайте действие по полной функции потерь, затратам rollout и guardrails. Стоп при EL выбранного действия < ε — байесовское правило в рамках модели, а не равномерная frequentist-гарантия для любого истинного эффекта. Проверьте правило симуляцией сетки сценариев, включая нулевой/отрицательный эффект и ошибочный prior.
6. ROPE [−r,r]: HDI внутри → практически эквивалентны; нижняя граница > r → B практически лучше; верхняя < −r → B практически хуже; иначе данных недостаточно. Частотный аналог эквивалентности — TOST.

## Согласование с частотным анализом

Для большого n, слабого prior и нормальной аппроксимации P(B>A)≈Φ(z), где z имеет знак B−A. Тогда односторонний p на пользу B равен 1−Φ(z): p=.17 соответствует примерно 83%, p=.047 — 95.3%. Для двустороннего p=.17 и положительного эффекта вероятность примерно 91.5%; без знака такого перевода нет. В малых выборках и при информативном prior эти приближения могут не работать.

Последовательное обновление posterior допустимо при корректной likelihood-модели и игнорируемом механизме остановки, но ежедневный порог P>95% сам по себе не контролирует частоту ложных побед в 5%. В симуляции урока 5.3 один заранее заданный взгляд даёт около 5%, ежедневные проверки — около 23% как для байесовского, так и для согласованного одностороннего частотного критерия. EL контролирует модельную цену решения, а не этот error rate.

## Бандиты

Thompson sampling оптимизирует накопленную награду: выборки θ из posterior каждой руки → выбрать максимум → обновить только выбранную руку. Считайте трафик по числу назначений, не успехов. В стационарной модели regret может расти логарифмически при соответствующих предпосылках; это не ограниченная константа. При дрейфе нужны окна/discounting и мониторинг, поскольку обычный TS может почти перестать исследовать прежнего аутсайдера. Обычный fixed-horizon тест по адаптивным данным не получает гарантий автоматически; для вывода существуют специальные адаптивные методы.

## Иерархические модели

Partial pooling снижает шум при обменности сегментов; проверяйте posterior predictive fit, чувствительность к prior и диагностику MCMC (R-hat, ESS, divergences). 0/40 при типичной конверсии 30% нельзя объявить обычным маловыборочным шумом: вероятность около 6.4·10⁻⁷. Гиперсреднее городских эффектов отличается от пользовательского эффекта: последний вычисляйте из draws со заранее заданными весами. Сравнивайте общую гипотезу с общей; Holm отвечает на семейство отдельных городских вопросов. Если отбираете города по posterior, оцените и потери/множественность такого решения.
