# Дизайн A/B-теста

## Чек-лист дизайн-дока (заполняется ДО запуска)

1. **Гипотеза**: потому что X → изменится Y → выиграет Z (проверяемая, с направлением)
2. **Метрики**: OEC (одна целевая: чувствительная + близкая к деньгам) + guardrails (что не должно упасть: латентность, отписки, поддержка) + инварианты (не должны меняться: SRM, размер групп)
3. **MDE**: минимальный эффект, интересный бизнесу (не «какой получится»); эффект меньше MDE — не обсуждаем
4. **Расчёт n**: `n_группы = 2·(z_{1-α/2}+z_{1-β})²·σ²/MDE²` — **множитель 2 обязателен** (двухвыборочность; классическая ошибка ×2 недобора)
5. **Длительность**: целые недели (сезонность пн/вс), проверить дневной трафик × недели ≥ n
6. **Юнит рандомизации**: юзер (не сессия/заказ!); analysis unit = randomization unit
7. **Decision rule 2×2**: значимо+плюс → ship; значимо+минус → откат; серое → нет решения (продлевать нельзя — peeking)
8. **Сплит**: какой слой/домен, пересечения с текущими тестами, ramp 1→5→50%

## Быстрые формулы
- 50/50 всегда мощнее (r·(1−r) максимален); 10/90 → мощности 0.64 vs 0.79 при том же трафике
- Сузить CI вдвое → данных в 4 раза больше (закон √n)
- Планируемая чувствительность ↑: CUPED с пре-периодом (экономия = ρ² наблюдений, при ρ=0.8 — 64%)

## Грабли
- «Запустим и посмотрим» = неявный дизайн с peeking-инфляцией α до 25–30%
- Мощность/MDE интерпретируются ТОЛЬКО на этапе дизайна; сравнивать наблюдаемый эффект с MDE нельзя — для этого CI
- Интерференция (двусторонний рынок, соцфичи) → geo/switchback-дизайн заранее
