# Сплит-система

Инфраструктура раскидывания трафика по вариантам: хеш-функция(user_id + соль + слой) → слот. Слои/слоты/соли позволяют параллелить эксперименты без пересечений (оверлап-система).

## Зачем
Очередь гипотез стоит денег — параллельные эксперименты на слоях (фронтенд/ранжирование/бэкенд) дают больше параллелизма; корректная рандомизация — фундамент валидности.

## Ключевые идеи
- Симулятор 11: одномерная схема (изоляция, но очередь) vs многомерная со слоями; двойное хэширование (соль+слой); одна группа не может быть контролем в двух тестах — эффекты не локализуются
- Deng гл.7: cookie-идентификация, hash-рандомизация, оверлап-эксперименты; Kohavi гл.4 (single-layer vs concurrent) и гл.12
- Бакеты: разбивают юзеров на 100–1000 корзин для гибкого управления долями (Симулятор 3, 11)
- Аудит системы: [[AA-тест]] + [[SRM]]-чек (koch-kir; X5 — SRM-чек на дашборде каждый час)
- Ошибки сплитилки: кривое разбиение, эффект памяти, зависимые данные (Симулятор 4)
