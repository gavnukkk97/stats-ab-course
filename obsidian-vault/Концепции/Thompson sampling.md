# Thompson sampling

Бандит-алгоритм: на каждом шаге семплировать параметр каждой версии из её текущего [[Апостериорное распределение|апостериора]] и показать версию с наибольшим семплом. Explore/exploit автоматически сбалансированы.

## Зачем
Эффективное распределение трафика между версиями: больше трафика лучшим вариантам, меньше — на исследование, минимум regret по сравнению с epsilon-greedy.

## Ключевые идеи
- Практика урока 5.4: симуляция бандита vs фиксированный A/B — сравнение regret (план)
- Анонсирован в дорожной карте X5 (урок 7 «Байес и бандиты») — слайдов нет, контент пишем сами
- Асимптотически оптимален для Bernoulli-бандитов; естественная байесовская реализация через [[Сопряжённость]] Beta-Бернулли
- Критика: смещение выборки (победитель собирает данные) — оценки эффекта по итогам бандита не являются несмещёнными
