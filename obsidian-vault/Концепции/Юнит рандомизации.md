# Юнит рандомизации

Сущность, которой случайным образом назначается вариант: user vs session vs order vs магазин vs курьер. Может не совпадать с юнитом анализа — и это ломает стандартные критерии.

## Зачем
Правильный выбор юнита определяет валидность (интерференция на уровне заказа = нарушение [[SUTVA]]) и чувствительность теста; mismatch юнитов — источник неверных p-value.

## Ключевые идеи
- Deng (гл.8): randomization unit vs analysis unit; вывод для ATE корректен при их согласовании; koch-kir: юнит анализа = юнит назначения тритмента
- Пример koch-kir: скидка на доставку — число заказов (поюзерная метрика, t-тест ок) vs средний чек ([[Ratio-метрика]], t-тест неверен)
- Симулятор 13: рандомизация по курьерам для метрики «время доставки» — юнит подбирается под механику эффекта
- Kohavi гл.14 Choosing a Randomization Unit: page vs user; HKU L1 — два принципа выбора
- Кластеры (магазин, регион, гео) как юнит — защита от интерференции ценой [[Дизайн-эффект ICC|design effect]] (abba, офлайн-ритейл)
