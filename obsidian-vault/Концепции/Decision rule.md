# Decision rule

Правило принятия решения, зафиксированное ДО теста. Базовая форма X5 — матрица 2×2 (знак OEC × состояние [[Guardrail-метрики|guardrails]]): OEC↑+guardrails OK → ship; OEC↑+guardrails просели → не раскатывать; OEC= → не раскатывать; OEC↓ → откат.

## Зачем
Без правила заранее решение принимается постфактум по настроению → p-hacking и «сделай зелёным». «Решение — продакту, а не p-value» (stats_for_science).

## Ключевые идеи
- Production-grade decision rules: типы метрик (success/guardrail/deterioration/quality), распределение α между типами тестов, поправка для β — формализация shelter (серия «Множественная проверка» гл.3)
- Пограничный p=0.049: «α=5% — конвенция, не закон физики» — раскатить на 50% и повторить тест (X5)
- Экономика решения: L1/L2 (цены ошибок) и срок жизни фичи → оптимальные α/β; EVI/VOI для приоритизации тестов (abba, «Экономика A/B-теста»)
- Карточка завершённого теста X5: гипотеза, OEC, guardrails, MDE, n, длительность, владелец, результаты, решение
- Analysis Plan / pre-registration как защита от p-hacking (shelter)
