# CUPAC

Control Using Predictions As Covariates (DoorDash, 2020) — обобщение [[CUPED]]: вместо одной ковариаты Y_pre — ML-прогноз метрики Y по сотне фичей, не затронутых тритманом. Ковариата валидна, пока не зависит от тритмана: модель обучается вне окна эксперимента, на периоде теста — только инференс.

## Зачем
Линейный CUPED ловит только линейную связь ковариаты с метрикой; нелинейный ML-прогноз объясняет больше дисперсии → сильнее снижение → короче тесты. Цифры X5: σ 151 → 114 (CUPED, −43%) → 94 (CUPAC, −61%), но CUPAC требует ML-инфраструктуры.

## Ключевые идеи
- Предок — Yandex BDT (Poyarkov et al., KDD 2016): бустинг над деревьями вместо линейной поправки, валидация на 161 реальном эксперименте
- Цель выбора модели — максимизировать R² по Y (бустинг деревьев на pre-experiment фичах); cross-fitting против утечек
- DoorDash: CUPAC в switchback-экспериментах логистики сократил длительность на 25%+ (Tang et al., 2020)
- Опасность: неверная спецификация/переобучение или «протекающие» фичи → bias; нужен [[AA-тест]]-контроль и мониторинг (кейс Авито — «ускорение проверки гипотез в пару дюжин раз», trisigma)
- Не сработает без истории: новые юзеры, короткие окна → гибрид pre- + in-experiment ковариат (Etsy, Deng KDD'23)
