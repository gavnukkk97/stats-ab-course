# Разбор для преподавателя

Исходы случайны; нельзя выставлять оценку по совпадению бинарного решения с заранее желаемым ответом.

1. Генератор включает всю eligible-популяцию в assignment. ITT знаменатель — 6000 пользователей. Отсутствие заказа означает 0 маржи; фильтрация только экспонированных меняет популяцию, даже когда trigger безопасен.
2. В exposure есть асимметричные ретраи; event_id тоже повторяются. Удаление точных повторов по идентификатору допустимо после проверки равенства содержимого. Считать SRM по сырым строкам exposure ошибочно. Это не основание автоматически выбросить весь assignment-анализ.
3. Дни от 0 до 13 принадлежат завершённому окну. День 14 не включается. Маржа в копейках, бизнес-порог 150 копеек =1,50 ₽. Отмена даёт нулевую маржу, но учитывается в бинарном guardrail «пользователь хотя бы с одной отменой».
4. Базовый анализ — Welch по пользовательской сумме маржи и односторонняя верхняя граница изменения доли пользователей с отменой. Ограничение normal-approximation для долей нужно проверить по числу событий. Для CUPED — заранее заданный pre-outcome и корректный adjustment; не сравнивайте его p с сырым effect без объяснения estimand.
5. Малый положительный эффект, заданный генератором, не обязан стать значимым в одной реализации. Отсутствие значимости не доказывает H0. Для разрешения rollout по строгому правилу требуются нижняя граница OEC выше 150 копеек и верхняя граница вреда guardrail ниже .005; иначе HOLD с объяснением неопределённости.
6. Подсчёт baseline variance и n не зависит от наблюдаемой дельты теста. Приближённо n_arm=2(z.975+z.8)²σ_pre²/150²; отдельно оговорите перенос дисперсии из pre в test и календарные ограничения.

Генератор сохраняет seed. Воспроизведение: `python course/capstone/solutions/generate_data.py`. Для приёмки реализации используйте проверки ключей, тождество суммы очищенных событий и пользовательской таблицы, сохранение всех назначенных пользователей и крайние случаи решения.
